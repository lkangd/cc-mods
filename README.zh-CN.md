# cc-mods

一组 Claude Code 模组（mod）。每个 mod 是 `mods/<mod 名>/` 下独立的插件：互相不依赖、不共享代码或数据，可以同时启用，各自有自己的安装和使用说明。

## 模组

| 模组 | 版本 | 功能 |
| --- | --- | --- |
| [chat-toc](#chat-toc) | 0.2.0 | 把当前会话的内容停靠在对话旁边；点一下跳回任意一轮 |

新增 mod 时，在上表加一行，并在下方与 chat-toc 同级加一节。

---

## chat-toc

在 Claude Code 的全屏终端里，chat-toc 把当前会话的内容停靠在对话记录右侧：每轮对话一条，点一下就跳回那一轮。

### 环境要求

- Claude Code `>= 2.1.287`（看 `claude --version`）
- 交互式终端。在 Claude Code Desktop（以及 VS Code、手机端）里内容能看到，但点击无法跳转：Claude 应用还不允许插件滚动对话（见[已知限制](#已知限制)）。不支持 JetBrains
- 全屏布局：用 `/tui fullscreen` 切换
- 终端足够宽：能不能停靠由 Claude Code 决定。在 2.1.287 和 2.1.295 上实测：从 144 列起自动停靠，用 `/chat-toc` 从 110 列起也能停靠
- 不需要 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS`
- 操作系统不限，但只在 macOS 上实测过（见[已知限制](#已知限制)）

内容不在屏幕上时，输入框上方有一行替身，可以把它打开（见[快速上手](#快速上手)）。

### 安装

两种方式二选一，不要同时用：

Marketplace（推荐）：

```sh
claude plugin marketplace add lkangd/cc-mods
claude plugin install chat-toc@cc-mods
```

装好后，`claude plugin list` 会显示 `chat-toc@cc-mods` 为已启用。

本地加载（开发用）：

```sh
claude --plugin-dir /path/to/cc-mods/mods/chat-toc
```

### 快速上手

1. 在全屏布局下启动 Claude Code。目录会自动停靠在右侧，标题为 "ChatTOC"（2.1.287 不画标题行）。
2. 如果目录没显示，说明终端比 Claude Code 自动停靠所需的窄，输入框上方有一行替身：`ChatTOC  ‹ ›  │  用户 12 轮 · Agent 80 步   展开目录 ❯  ✕`。行太窄放不下时，计数从末尾起缩短，再连名字一起去掉；Claude Code Desktop 不画 `‹ ›`。把终端加宽，目录会自动停靠，这一行随之消失；或者点 `展开目录 ❯`（或运行 `/chat-toc`）：Claude Code 也会在更窄的终端里停靠它，放不下时放在输入框上方。不在全屏布局时目录会自动开在输入框上方；用 `/tui fullscreen` 可让它停靠在右侧。

3. 点任意一条跳回对话中的那一轮。用 ✕ 关闭目录后，随时用 `/chat-toc` 再打开，焦点落在目录里。

### 操作

| 操作 | 效果 |
| --- | --- |
| 点一条目里你自己的输入（从 `●` 行起） | 跳到那条输入，置于屏幕顶端，并选中该条目；不会打开预览。斜杠命令或 `!` 命令跳到它后面那一行，输入行保持在视野内 |
| 点一条目里 Agent 的回复（从 `├╴` 行起） | 跳到该轮最后一段文字回复（没有文字时，跳到该轮最后画出的内容），并选中该条目 |
| 点筛选行下方那排竖条中的一根 | 跳到那一轮，与点它的条目一样，但不选中。每轮一根，高度按 Agent 的步数；轮数超过窗格宽度时一根代表多轮，跳到其中第一个能跳转的。你所在那一轮的竖条是亮的那根。少于两轮或窗格很矮时隐藏 |
| 在目录上滚滚轮 | 目录按条目滚动，并暂停跟随 |
| `Ctrl+X` 然后 `Tab`；或提示符为空时 `/chat-toc` | 把焦点移进目录 |
| 提示符为空时在目录里任意点击 | 也把焦点移进目录，下面的按键立即生效。`r: 填入` 之后不行（焦点去输入框）、点 `‹ ›` 不行。输入框里有文字时焦点留在输入框。不是目录按键的键会回到输入框并输入在那里；是目录按键的（`c`、`p`、`r`、`f`……）作用于目录 |
| `↑` `↓`（焦点在目录里） | 逐个移动选中（你的输入和 Agent 的回复各算一个）；被选中的行反色。移动选中不会打开预览，已开的预览留在原地。不能跳转的条目也可以选中 |
| `Enter`（焦点在目录里） | 与点选中一侧相同：跳转并保持选中 |
| `p`，或点选中条目下方那行的 `p: 预览` | 在那一轮上打开预览。预览关闭时那行会显示：`p: 预览 · r: 填入 · c: 复制`，每个按钮只在能用时出现（见下方预览各行）；`r` 填回该轮的输入，`c` 复制选中的一侧（你的输入，或 Agent 的最后文字回复）。`↑` `↓` 会越过这一行 |
| `1` `2` `3`，或点顶部的 `1: 全部` `2: 用户` `3: Agent` | 显示全部 / 只显示你的输入 / 只显示 Agent 的回复。选中的那个下方有一条高亮色的粗线。跨会话记忆 |
| `l`，或点页脚右端的 `布局 卡片` 按钮 | 按卡片 → 紧凑 → 时间轴循环切换布局；按钮名显示当前布局。跨会话记忆 |
| `p`，或点预览顶行右端的 `p: ✕` | 关闭预览，区域和展开状态都一样；列表收回行数，选中条目下方那排按钮回来。不记忆：目录每次打开时预览都是关着的 |
| `e`，或点预览最后一行的 `e: 展开` | 让预览盖住列表和那排竖条：整轮完整显示，可用滚轮、`PgUp` `PgDn` 或 `↑` `↓` 滚动。再按 `e`，或点顶部的 `e: ← 返回`，回到列表在上、预览在下的状态；`Esc` 也可以。因目录太矮而自动展开的预览，按 `e: ← 返回` 即关闭 |
| `r`，或点预览 `用户` 行的 `r: 填入` | 把预览里的输入按原样放回输入框作草稿：输入框为空时直接放入，否则放在你正在打的文字之后、隔一个空行，绝不覆盖。绝不发送：要自己改或自己按 `Enter`。Agent 工作时也能用（`Enter` 照常排队）。焦点移到输入框。`!` 命令没有 `r: 填入`（填进去会被发给模型，而不是执行） |
| `c`，或点预览 `用户` 行的 `c: 复制` | 完整复制那份输入，按你打的原样（`!` 命令复制成 `!command`）；按钮显示 `已复制` 约 2 秒。焦点留在目录里 |
| `a`，或点预览 `Agent` 行的 `a: 复制` | 完整复制 Agent 最后一段文字回复，按 Markdown 原文；按钮显示 `已复制` 约 2 秒。该轮进行中时不出现 |
| 点筛选行下方的搜索框，或按 `f`（`f: 搜索`） | 焦点移进搜索框。输入词语或文件路径的一部分：列表收窄到同时含所有词的那些轮 |
| 搜索框里按 `Enter` | 跳到离当前所看轮次最近的匹配轮，并结束搜索（列表恢复完整，跳到的轮高亮）。没有匹配时只清空搜索框 |
| 搜索框里按 `↓` 或 `Tab` | 选中移到匹配的条目上；在其中一个上按 `Enter` 跳过去、选中它并保留搜索 |
| 搜索框里按 `Esc` | 焦点回到输入框，搜索保留 |
| 搜索框里按 `Ctrl+U` 或退格，或点它右端的 `✕` | 清空搜索 |
| 点搜索行右端的 `‹` 或 `›`，或内容不在屏幕上时点输入框上方那行的；或按你绑定给它们的键（见[上一轮和下一轮的按键](#上一轮和下一轮的按键)） | 让对话记录跳到当前所看轮次（即高亮那一轮，不是 `↑` `↓` 的选中）之前或之后一轮，范围限于列表当前显示的轮：视图选择生效，搜索中则只在匹配里跳且不结束搜索。跳到该视图显示的那一侧（全部和用户视图是你的输入，Agent 视图是回复），高亮留在跳到的轮上，所以每按一次多走一轮。到两端再按无动作。不能跳转的轮会被越过；那一侧确实没有能跳的轮时，列表下方显示"这一条当前没有显示在对话里，无法跳转"，内容不在屏幕上时显示在屏幕右上角 |
| `Esc`（焦点在目录里） | 焦点回到输入框；目录保持打开 |
| `Ctrl+X` 然后 `←` / `→` | 加宽 / 收窄目录（Claude Code 的功能）。手动设过的宽度优先 |
| 点 ✕ | 关闭目录；本会话内不再自动打开。新会话（包括 `/clear` 或 `/resume` 之后）会重新打开 |
| 点输入框上方那行的 `ChatTOC` | 打开目录，与 `展开目录 ❯` 一样。Claude Code Desktop，以及 2.1.303 之前的终端，把它画成普通文字色 |
| 点输入框上方那行右端的 `✕`（2.1.295 之前紧跟在 `展开目录 ❯` 后面） | 隐藏这一行，本会话和之后的每个会话都不再显示，并提示如何找回。`/chat-toc` 仍能打开目录 |
| `/chat-toc-band` | 重新显示输入框上方那一行 |
| `/chat-toc` | 目录关着时打开它；开着时把它带到最前（被别的窗格顶到后面时也一样）；两种情况下都把焦点移进去（提示符为空时）。它从不关闭目录 |
| Claude Code Desktop：点一条条目 | 在该轮条目的正下方打开预览，圆角边框的框；点另一条移到那里。打开时不滚动目录：落到下边缘之下时，自己滚过去看。点击也会请求跳转，Claude 应用会一言不发地拒绝（见[已知限制](#已知限制)） |
| Claude Code Desktop：在视图选择下方的搜索框打字 | 与终端一样随时收窄列表；那排竖条把匹配的轮画成强调色，其余变暗。没有 `f: 搜索`：点搜索框本身 |
| Claude Code Desktop：搜索框里按 `Enter`，或它的 `预览` 按钮 | 保留搜索，在最新的匹配轮上打开预览（应用无法跳转，也说不出当前看到哪一轮） |
| Claude Code Desktop：点预览顶行的 `✕`、最后一行的 `↓ 还有 12 行 · 展开`、`← 返回` | 同终端的 `p`、`e` 和 `e: ← 返回`。Desktop 没有快捷键，按钮上不写键名 |
| Claude Code Desktop：滚动目录；点列表顶部的 `↑ 更早的 12 轮`、底部的 `↓ 更晚的 12 轮`、最后一条之后的 `↑ 回到顶部` | 应用把整个目录、视图选择和搜索框一起滚。长对话列出最新的轮（多到应用一次绘制装得下为止，卡片布局约 45 轮）；`↑` 列出更早的轮，`↓` 回到较新的轮，两者都会关掉已打开的预览。搜索或视图选择先收窄列表。`↑ 回到顶部` 把目录滚回视图选择处 |
| Claude Code Desktop：点预览 `用户` 或 `Agent` 行的 `复制` | 与 `c` 和 `a` 相同；应用收不下的复制显示"太长，无法在此复制"。Desktop 没有填入 |

快捷键 `1` `2` `3` `l` `p` `e` `f` `r` `c` `a` 只在焦点位于目录里时生效；焦点在搜索框里时不生效，搜索框吃掉所有字母；`p` `r` `c` 只在选中条目那行或已打开的预览显示对应按钮时生效；`e` `a` 只在预览打开时生效，`e` 还只在预览被裁剪或展开时生效（`a` 在短预览裁掉 `Agent` 行时不行，`e` 之后才行）。`‹` `›` 没有快捷键，`↑` `↓` 会越过它们。

### 上一轮和下一轮的按键

chat-toc 不绑定自己的按键。`‹` 和 `›` 响应两个在普通会话里空闲的 Claude Code 键绑定动作，你可以在 `~/.claude/keybindings.json` 里给它们绑键，从输入框一步步翻对话，Agent 工作时也可以：

```json
{
  "bindings": [
    {
      "context": "Global",
      "bindings": {
        "meta+k": "app:toggleDiffNoiseFilter",
        "meta+j": "app:toggleDiffPreSession"
      }
    }
  ]
}
```

- `meta+k` 是上一轮，`meta+j` 是下一轮。动作名对不上是因为插件不能新增动作：chat-toc 借用了 Claude Code 为 diff 视图命名、普通会话用不到的两个动作。
- macOS 上终端必须把 Option 当 Meta 发（iTerm2：Profiles → Keys → Left Option key: Esc+；Terminal：设置 → 描述文件 → 键盘 → 勾选"将 Option 键用作 Meta 键"）。
- 用带修饰的键如 `meta+k`，不要用和弦如 `ctrl+x p`，也不要用裸键：和弦没有响应时（目录和输入框上方那行都不在），它的第二个键会被打进输入框；裸键则永远到不了按钮。
- 这些键按的是目录里画的 `‹` `›`，目录不在屏幕上时（关闭、等待停靠、或被别的窗格挡住）按的是输入框上方那行的。什么时候彻底没响应，见[已知限制](#已知限制)。

### 显示内容

- **条目**：每个条目是会话的一轮：你的一次输入，加上从这次输入到你下一次输入之间 Agent 做的事。按对话顺序。一个斜杠命令、一个 `!` 命令各自是一条独立条目；同一段提示词提交多次就是多条；Agent 工作时排队的提示词也是独立条目。后台任务通知和 `/loop` 启动的工作并进它们前面的那条条目。子代理（subagent）里的任何内容都不显示。
- **时间轨道**：条目挂在左侧一条竖线上。你的输入从节点 `●` 开始，Agent 的回复从分支 `├╴` 开始；它们后面的行、同一天各组之间的空隙都贴着竖线 `│`。
- **你的输入**：前 2 行，放不下时行尾加 `…`。斜杠命令显示为 `/command args`，`!` 命令显示为 `!command`；代码块、Markdown 标记和粘贴标记不显示，只有图片的输入显示"（只有图片）"。折行时，逗号和句号永远不会开一行，14 个字符以内的英文单词和文件路径整体下移。
- **Agent 的回复**：暗色文字，先是状态和步数，然后是最后一段文字回复，至多 2 行：
  - `N 步 · 回复…`：步数是主 Agent 这一轮调用了多少个工具；并行调用每个算 1，子代理算 1，中间的思考和文字不算。0 步时不显示计数，只有回复。
  - `N 步 · 无文字回复`：该轮结束时没有文字回复。
  - `已中断 · N 步`：你中断了这一轮。
  - `出错 · N 步 · 错误信息`：该轮以 API 错误结束。单个工具调用失败不算出错。
  - `进行中 · N 步`：Agent 还在处理最后一轮；分支旁有一个橙色 `◐`，步数实时增加。
  - 本地斜杠命令，或没有让 Agent 动起来的 `!` 命令，只有你的输入。这类条目在"Agent"视图下隐藏。
- **时间和日期**：时间来自 transcript，用本机时区。卡片布局把时间写在你输入第一行的右端（`HH:MM`）；紧凑和时间轴把时间写在左侧一列，每轮第一行。日期变化处（包括列表顶部）有一条线 `─ 10月9日 ───`；今天显示 `今天 · 10月13日`，另一年的日子带年份。读不出时间的轮不显示时间也没有日期线；不做猜测。
- **压缩**：对话被压缩过的地方，列表上有一条虚线，`/compact` 是 `╌ 已压缩 14:32 ╌╌╌`，自动压缩是 `╌ 自动压缩 14:32 ╌╌╌`，带发生时间（不含 token 数字）。它绝不切断一轮：`/compact` 的虚线在 `/compact` 条目之下；自动压缩发生在提交某轮时就在那一轮之前，发生在某轮中间就在那一轮之后（进行中的轮则在列表末尾，直到下一轮出现），发生在两轮之间就在两轮之间。它像日期线一样把时间轨道断开，每种布局都如此，并在每种视图选择下都显示在所显示的轮之间；两条挤在同一组显示的轮之间时合并成一行带计数和最后一条的时间，`╌ 已压缩 ×3 · 14:32 ╌`。与日期线相遇时，日期线在前。它上面的条目不变暗。
- **更早的轮次在别处**：本会话的文件从一次压缩开始、且不含更早的轮次时（用 `--fork-session` 分叉的会话，或恢复后先被压缩的文件），列表顶部有一条暗色文字："更早的轮次不在本会话的文件里"。更早的轮次不会从别处读取。
- **三种布局**：卡片（默认）每侧至多 2 行，时间在右端；紧凑每侧 1 行，时间在左列；时间轴每侧至多 2 行，时间在左列。布局只改变条目怎么画，不改变显示哪些。切换时，选中的条目（没有选中时则是正在看的那轮）保持在视野内。
- **高亮**：标记你正在对话记录里看的那一轮（握住屏幕顶行的那轮；对话末尾完整可见时是最后一轮）：节点变成 `◉`，分支变成 `┣╸`，该轮的线变粗为 `┃`，与时间一起用高亮色。高亮和暗色文字跟随 Claude Code 的主题（`/theme`）；高亮是 Claude Code 菜单里选中项的颜色，主题一变目录立即跟随。点击跳转后，高亮留在跳到的轮上，直到你再次滚动对话记录。`!` 命令的轮（以及用 `--resume` 打开的会话里本地斜杠命令的轮）在对话记录里没有对应的行可定位：当屏幕顶行只有这样的行时，高亮落到下一轮。高亮与 `↑` `↓` 选中（反色）相互独立，可以在不同条目上。指针悬在条目上时，那一侧的文字变高亮色，指针正下方那条线反色。
- **搜索**：视图选择下方那行有 `f: 搜索` 和搜索框（空的时候显示"词或文件路径"）。搜索把列表收窄到含每一个输入词的轮（词按空格切分），匹配范围：你按原样输入的文本（含代码块和粘贴的内容）、Agent 最后一段文字回复的全文、该轮改过或读过的文件的完整路径。不区分大小写，全角半角字母同等匹配，中文等其他文字按普通子串匹配；不支持正则、模糊匹配和引号短语。搜索跟随视图选择：全部搜所有字段，用户只搜你的输入，Agent 只搜回复和路径。行的右端显示匹配多少轮（`4 / 38`），然后是 `✕`，再是 `‹ ›`（常驻，见[操作](#操作)）；没有匹配时列表显示"没有匹配的轮次"。新的匹配轮会加入列表，进行中的轮边写边参与匹配。搜索时，列表让离当前所看轮次最近的匹配保持在视野内（优先它之前最近的，否则之后第一个），只有那一轮本身匹配时才显示高亮，压缩线仍留在显示的轮之间，那排竖条点亮含匹配的竖条而不是你所在的那根（无匹配时全部变暗）。搜索跨视图或布局切换、新轮次、其他窗格在前、关闭再打开目录一直保留，直到 Claude Code 退出；它绝不会被存储。
- **顶部与页脚**：顶部是三个视图选择、其下标示所选的线、搜索行，然后是那排竖条和列表。页脚在目录底部、预览打开时在预览之下：一条细线，线下左侧是轮数（"12 轮"，各种视图选择下都一样），右侧是布局按钮。
- **上下文用量**：上一次回复时上下文窗口的占用程度，按 Claude Code 报告的显示，跟在页脚轮数后面："38 轮 · 上下文已用 62%"；目录窄时缩成"38 轮 · 已用 62%"，再窄就去掉。输入框上方那行替身也会在计数后加"· 上下文已用 62%"。它在会话开始时和每次回复后读取，永远暗色、不着色，接近上限时也不说任何话（Claude Code 自己会在压缩前警告）。第一次回复之前、以及一次压缩之后到下一次回复之前，Claude Code 没有数字，就不显示。
- **预览**：底部、页脚上方的一个区域，完整显示一轮。默认关闭，要你开口：按 `p`，或点选中条目下方那行的 `p: 预览`，就在那一轮打开；之后你滚动对话记录、用 `↑` `↓` 移动选中、切换视图或布局、有新轮次到来、或搜索把它那轮挤出列表，预览都停在那一轮上。从另一条条目打开时移到那里。点击或 `Enter` 一条条目、搜索框里按 `Enter`、那排竖条、`‹ ›` 和输入框上方那行都不会打开它。用顶行右端的 `p: ✕` 关闭；它的轮离开对话时（回退、`/clear`、另一个会话）也关闭；目录每次重新打开时都关闭；它绝不会被存储。搜索时，如果它显示的那轮匹配，那行数据末尾加"匹配：用户 · Agent · 文件"，匹配的文件排在文件行的第一位（只读过没改过的匹配文件也列在那里）。顶行是 `─ 预览 ─── p: ✕`；其下：
  - 一行暗色数据，来自 transcript 对该轮的记录：`10月16日 14:32 · 12 步 · 3 分 20 秒 · 输出 3.5k`。日期总是显示，今天也一样；状态（`进行中`、`已中断`、`出错`）只在没正常结束时显示。时长是模型工作的时间（`45 秒`、`3 分 20 秒`、`1 小时 5 分`、`<1 秒`），按该轮各次模型调用累计，transcript 记录了才显示；token 是主 Agent 写出的（`输出`），每次回复计一次，transcript 记录了才显示。不做估算：transcript 没写的数字一律不显示。这行超出目录宽度时，末尾的数字整体逐个省去；
  - `用户`，右端有 `r: 填入 · c: 复制`，然后是你的输入，按你打的原样：代码块和粘贴的内容保留，斜杠命令为 `/command args`，`!` 命令为 `!command`。只有图片的输入两个按钮都没有；图文混合的输入只填/复制其文字，并提示"图片未包含"；
  - `Agent`，右端有 `a: 复制`，然后是 Agent 最后一段文字回复，按 Markdown 绘制；进行中的轮显示目前已写的最新文字，没有 `a: 复制`；
  - 该轮涉及的文件：`改 register.tsx、pane.tsx +1 · 读 5`。"改"是 Agent 编辑或写过的文件，以及 Claude Code 记录到的被 shell 命令改动的文件；"读"是 Agent 读过的文件；既读过又改过的算改。路径在会话目录内时相对该目录，否则完整路径并对你用户目录用 `~`。
  预览的高度取决于目录的高度，不取决于轮的内容（约为顶部以下行数的 40%，4 到 14 行），所以按另一条条目时列表不会跳。放不下的部分被裁掉：先裁文件行，再裁 Agent 的回复，最后是你的输入；最后一行随之变成 `↓ 还有 12 行 · e: 展开`。关闭时不占行：行数还给列表。行数不够时，先撤那排竖条，已打开的预览缩到 4 行；连 4 行都放不下（列表还要 8 行）时，`p` 改为直接展开打开，`e: ← 返回` 关闭它。
  展开（`e`）后，预览取代列表和那排竖条，在视图选择之下、页脚之上，完整不裁地画那一轮：文件在 `改过` 和 `读过` 之下每行一个。你滚动对话记录或有新轮次到来时它仍停在那轮，进行中的轮在里面继续增长。特别长的输入或回复在这里也会裁，两者合计约 60,000 字符，裁掉处有一行：`… 还有 12,345 字未显示 · c: 复制`（回复之后是 `a: 复制`）。
- **填入与复制**：按钮作用于预览显示的那轮，或选中条目下方那行对应的轮，按下时才读 transcript；什么都不保存。输入框非空时不会有额外提示。填入没有成功时在提示里说明原因："无法填入：有对话框打开"（文字丢弃，不留待以后）或"无法填入：被其他插件拒绝"。Claude Code 报告复制失败时说明原因，如"太长，无法在此复制"。
- **跟随与暂停**：目录自动滚到高亮的轮；对话记录在末尾时停在最新条目。手动滚动目录，或焦点在目录里，都会暂停跟随；高亮下一次移到另一轮时恢复跟随（你把对话记录滚到另一轮，或点击跳转）。高亮在其他窗格挡住目录期间变化时，目录一回到最前就补上。
- **不能跳转的条目**：用 `--resume` 打开的会话（或在会话里 `/resume`），恢复前被压缩掉的轮从一开始就挂在空心标记上（你的输入在 `○`、文字变暗，Agent 的回复在 `├┄`）。它们仍可选中、可点击；跳转无法完成时，列表下方出现一行黄色（主题的警告色）、以 ⚠ 开头的文字，先反色闪烁 3 次：被压缩的轮显示"这一条在压缩之前，恢复会话后无法跳转"，否则显示"这一条当前没有显示在对话里，无法跳转"。这行文字在下一次跳转、移动选中或约 5 秒后消失；跳不过去的那一侧此后保持空心标记，直到 Claude Code 再次画出那一行为止。
- **列表下方的提示**：
  - "有 N 行无法识别，目录可能不完整"：transcript 有 N 行读不出来（比如 Claude Code 改了格式）；目录其余部分照常显示。
  - "没有权限读本会话的 transcript，目录无法显示"或"读不到本会话的 transcript，目录无法显示"：此时目录宁可一条不显示，也不显示残缺的列表。
- **空目录**：新会话在第一条消息之前显示"本会话还没有对话"；用 `--fork-session` 或 `--resume` 打开、文件还没写出来的会话显示"本会话还没写进 transcript 文件，提交第一条消息后显示目录"。
- **会话变化时**：
  - `/clear`：目录清空并按新会话重建（它的第一条就是 `/clear` 本身），没有分隔线。
  - 压缩：更早的条目仍然显示，在发生处有一条压缩线；上下文用量离开页脚，直到下一次回复。
  - 回退（包括 Esc Esc）：对话一恢复，被扔掉的部分（包括回退到的那条，其文字已回到输入框）立刻离开目录，不等下一次提交。回退后不提交就退出、再恢复，那部分随对话一起回来。
  - `--resume`、`--continue`、会话内 `/resume`、`--fork-session`：目录按那个会话重建，能跳到从没显示过的久远轮次。
  - 多个终端各自只显示自己的会话。
  - 会话进行中启用 chat-toc（在 `/plugin` 里启用，或 `claude plugin enable` 后 `/reload-plugins`）：不用重启；目录立刻列出至今的对话。找不到本会话的 transcript 时显示"提交下一条消息后显示目录"。
- **与其他停靠窗格**（如 `/diff`）：它们按 Claude Code 的标签页规则共享停靠区。新打开的窗格总是到最前；chat-toc 被顶到后面时不抢焦点，输入框上方那行像目录关闭时一样显示（`ChatTOC  ‹ ›  │  …   展开目录 ❯  ✕`）；回到最前时目录重新绘制，这行消失。
- **终端变窄**：终端窄到 Claude Code 把停靠的目录挪到输入框上方时，它留在那里，条目照常列出；加宽后重新停靠。
- **语言**：文字跟随系统语言：`LC_ALL`、`LC_MESSAGES`、`LANG` 中第一个有值的以 `zh` 开头时用中文，否则英文。中文版界面文字是代码的一部分。本中文 README 引用中文文字。

### 数据与隐私

- 只读当前会话的 transcript 文件（Claude Code 自己写的那份），沿当前分支取行。超过 4 MiB 后用一个只读的本地 `sh`（`dd` 加 `head`；Windows 上用 Windows PowerShell）按偏移分块读。
- 不写任何文件，不留任何存档，从不上网，没有同意流程。
- 插件的存储只保存三个偏好：视图（全部 / 用户 / Agent）、布局，以及输入框上方那行是否被隐藏。预览是否打开、开在哪一轮只存在内存里（更早的 0.2 构建为预览存过一个值，现在被忽略）。提示词文本、你输入的搜索词、文件路径、时长和 token 数都只在内存里，只出现在目录画出的内容中，绝不进入存储、日志或错误信息。文字只有在你按 `r`、`c` 或 `a` 时才进入输入框或剪贴板。

### 卸载

1. 运行 `claude plugin uninstall chat-toc@cc-mods`（本地加载的，去掉 `--plugin-dir`）。
2. 卸载后，偏好可能留在 `~/.claude/plugins/store/chat-toc_*.json`（marketplace 安装是 `chat-toc_cc-mods-*.json`，本地加载是 `chat-toc_chat-toc-local-*.json`；更早的构建写的是 `chat-toc_inline-*.json`；设置了 `CLAUDE_CONFIG_DIR` 时在其 `plugins/store/` 下）。愿意就手动删掉；无论哪种里面都没有提示词文本。

### 已知限制

- 低于 Claude Code `2.1.287` 时插件既不检查也不提示。
- 在 Claude Code Desktop 里目录只能看不能跳：Claude 应用对插件的每次滚动请求都回 `transcript not scrollable here`，也不告诉插件对话滚到了哪里，所以当前所在轮没有高亮；点条目会尝试跳转，应用拒绝时一声不吭，并且本会话内不再尝试。在 [anthropics/claude-code#100610](https://github.com/anthropics/claude-code/issues/100610) 跟进。Desktop 的样子是在 Claude 应用里肉眼核对的；VS Code 和手机端只有元素树测试覆盖；不支持 JetBrains。
- 终端上的复制无法确认：Claude Code 无论剪贴板收到什么都报成功（机器上没有剪贴板工具，或终端丢弃转义序列时，什么都没到，`已复制` 照样显示）。
- 提示词里的图片不填入、不复制，只有文字。
- 只在 macOS 上真正验收过。Linux 和 Windows 只核对了读大文件生成的命令，没有在真实机器上跑过；Windows 只用系统自带的 Windows PowerShell 5.1。
- transcript 文件格式不公开。Claude Code 一旦改动，目录可能只显示一部分，底部会写有多少行读不出来。
- 会话进行中启用时，transcript 的位置靠 Claude Code 未公开的目录命名规则推算；规则一变，目录要等你下一次提交才有内容。
- 跳到 `--resume` 前被压缩的行没有保证（`--resume` 下它们从一开始就挂空心标记）；跳不过去时列表下方的提示会说明，那一侧保持空心标记。
- 预览在 Claude Code Desktop 里不显示时长，多数被中断的轮也不显示：transcript 在那里没记录。
- 预览的 token 只是主 Agent 的输出；子代理写的不计。
- 特别长的提示词或回复在展开预览里也会被裁（复制拿到的是全文）。
- 分叉的会话不显示父会话的轮次：列表顶部一行文字说明更早的轮次不在本会话的文件里。
- 上下文用量在 Claude Code Desktop 里不承诺：没在那里测过，只在 Claude 应用给出数字时显示，在那排竖条之后的轮数后面。
- Desktop 没有填入，只有复制：Claude 应用报告填入成功，但它的输入框有时不显示文字。等应用的版本能可靠显示填入内容后，填入会在那里恢复。
- 三种布局的样子、高亮与反色选中能否分辨，靠人工核对，不阻塞发布。
- 不承诺每台机器上的固定速度；发布的性能数字来自一台参考机（Apple M1 Pro 的 Mac：20 MB 量级的长会话，Claude Code 画出最后一轮后约 0.7 秒内目录显示完毕，滚动和跳转不卡顿）。
- 目录位于输入框上方时（不在全屏布局，或无法停靠处）：它的布局、跟随和高亮没有验收。
- PTY 验收测试查的是中文文字；英文文字只有单元测试覆盖。
- 上一轮和下一轮的按键依赖两个借来的动作名，后来的 Claude Code 可能把它们占为己有；到那时按键会无声失效。输入框上方那行被折叠（`Ctrl+X` `Ctrl+A`）、正处于工具权限询问、或在 Claude Code Desktop（它不画 `‹ ›`，本来也不能跳转）时，按键没有响应。只有标签页切换时（点标签、`pane:next`）Claude Code 不重画输入框上方那行，所以 chat-toc 刚被那样顶到后面时，按键可能要到别的事情引起重画（新消息、一次回复、窗格开或关）才恢复响应；打开另一个窗格（如 `/diff`）会引起重画。
