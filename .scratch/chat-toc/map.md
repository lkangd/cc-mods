# chat-toc MVP

## Destination

Every decision on chat-toc MVP's features, interaction, compatibility and acceptance is settled, enough to sum up directly into a spec and an acceptance plan for an implementer (planning only, no implementation).

## Notes

- Talk to the user in Chinese; everything tracked in git, commit messages included, is in English (see `AGENTS.md`).
- The plugin root is `mods/chat-toc/`; it depends on no other plugin.
- Only the public Claude Code mods API, nothing the host does not publish; the one exception is reading the current session's transcript file (format unpublished), the TOC's data source. Large files are read in chunks with the system's `dd` to seek plus `head` on macOS/Linux (`tail -c +N` is too slow on macOS), and the built-in Windows PowerShell 5.1 on Windows. Minimum Claude Code `>=2.1.287` (the version where mods are on by default in the terminal and `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` is ignored from then on); the local version (2.1.295 for now, upgraded at any time) is a measured sample, not a version lock.
- Target surface: the interactive terminal's fullscreen layout, the Pane docked to the right of the transcript (`placement: 'dock'`). Opening by itself does not accept an inline placement; when it cannot dock, the status line keeps saying why and how to meet the condition. The one exception: when the person opens it with `/chat-toc` and the host places it inline, it stays as placed (the inline form is not promised, see the spec).
- Data: everything comes from the current session's transcript file (the current branch's conversation chain), with `$.session.messages()` only as a supplement; nothing written to disk, no archive, no consent flow. Only the main conversation loop; subagents stay out of the TOC. After `/clear` the contents rebuild with the new session, with no dividing line; entries from before a compaction still show; a branch thrown away by a rewind does not.
- The entry unit is the Turn group (User input + Agent reply). A User input is anything the person typed in the prompt and submitted with Enter, slash commands included. The Agent reply shows "N steps" plus the first 2 lines of the turn's last text; in progress it shows "in progress · N steps", without a text reply "N steps · no text reply". The user side shows "you · time" plus up to 2 truncated lines of the original text; the time comes from the transcript row's timestamp, and is not shown, never invented, when it cannot be read.
- A three-state View filter at the top, "All / User / Agent", All by default, the choice remembered globally across sessions (`$.store`). Three Layouts (Card / Compact / Timeline), switched by the person, also remembered across sessions.
- Opens by itself at each session start; once the person closes it, it stays closed for the session, `/chat-toc` reopens it, and the next session opens it by itself again.
- A click on the user side jumps to that prompt, on the Agent side to the turn's last text reply; with the focus in the Pane, ↑↓ select and Enter jumps. After a successful jump the highlight locks on the target group until the viewport next changes; the TOC scrolls to follow the Current position; a long session scrolls continuously and may render on demand, never in pages.
- The interaction follows cc-switch's (https://github.com/farion1231/cc-switch) "conversation contents" on the right of its session details.
- Host API facts follow the type declarations the `plugin-authoring` skill writes and `~/.claude-code-docs/docs/plugins__mods__*.md`; PTY acceptance can be driven with cmux.
- Domain terms are in [`CONTEXT.md`](../../mods/chat-toc/CONTEXT.md).

## Decisions so far

- [Decide the first release's form and docs](issues/16-grill-release-and-docs.md): first version `0.1.0`; evidence in a folder per version, and every version bump reruns every MUST; the root README holds the one user document (a ten-section outline in the words on screen, with the list of what is not promised), and `mods/chat-toc/README.md` holds only development and the release checklist; the marketplace entry has no category, and independence is stated only in the README; the entry, that README section and the evidence report go into one release commit once every MUST passes, no tag; a local folder marketplace smoke before the release, an install-level check from GitHub after it, withdrawn on failure.
- [Decide the Layout switch's entry and default](issues/13-grill-layout-switch-entry.md): Card by default; the one entry is the "Layout:<current Layout>" button at the filter row's right end, cycled by a click or by `l` while focused; no `v`, no command argument; no permanent footer; a switch anchors on the selected group or the Current position's group, and following stays as it was; `/chat-toc` takes no argument and only opens, brings forward and focuses, never closes.
- [Draw the three Layouts with label-only Buttons](issues/15-prototype-label-only-button-layouts.md): all three Layouts use "one Button per line": a `plain` Button per line, a side's lines sharing one jump, the card's head line `dimColor`, hover lighting a whole side through a hover scope; the highlight bar and the time column sit in a separate `Text` left of the Button, aligned on both versions; ↑↓ land on an entry's first line; Button has no `bold`, so the highlight is no longer bold, only the cyan mark; the mod folds and truncates on its own. All nine combinations draw and click on 2.1.287 and 2.1.295.
- [Decide how to share the dock with other Panes](issues/14-prototype-dock-coexistence.md): follow the host's tab rules: a newly opened Pane is always in front, chat-toc's own opening included; no taking the front back, no notice; when the other closes, the host brings chat-toc forward and it draws the latest state; the close mark counts only a person's close of its own id; nothing is drawn in the background, and a Current position change in the background cancels the follow pause, so it follows once in front. Also found: `session.start` does not fire on `/clear`, so `CT-LIFE-002`'s reopening relies on `classic.SessionStart` (source `clear`/`resume`).
- [Measure the cost of reading and drawing a long session](issues/12-task-measure-long-session.md): 20 MB is fast enough on both versions, given chunked reads with `dd`+`head`, regrouping only the last group while the file only grows, entries cached per group with only the window drawn, and a binary search for the Current position; rereads are triggered 300 ms after `session.append`/`turn.complete`, no polling; `CT-PERF-001`'s limits: first listing ≤4 s after the transcript, whole read ≤1 s, each incremental read ≤150 ms, the Pane's own work ≤16 ms (≤100 ms with the host), Current position ≤2 ms. Also found that 2.1.287's `Button` takes only `label`, raised as a new ticket.
- [Finalise the compatibility and acceptance contract](issues/06-grill-acceptance-contract.md): three levels (MUST / stated fallback / not promised), and a release only with every MUST present and none skipped; promises `>=2.1.287` fullscreen, any OS, `--plugin-dir` and the marketplace, with the gate run only on this macOS machine on the minimum and current versions; evidence in three layers, `claude plugin test` automation, cmux PTY and a visual check (not MUST), with consistency checked by an independent verifier against the transcript's conversation chain; set the `CT-*` MUST list and the not-promised list, the report in `mods/chat-toc/tests/evidence/<version>/`; the performance limits, Layout entry and Pane coexistence refer to three newly raised tickets.
- [Prototype the docked TOC Pane's look and interaction](issues/05-prototype-toc-pane.md): all three Layouts kept, switched by the person; filtering, jumping, highlight and cursor, the follow pause and the lifecycle (including reopening after `/clear`) all tried and passed, the highlight locking on the target group after a jump. Measured: a local command is a `system/local_command` row; a `ToolGroup` id matches on its first 24 characters; the fullscreen transcript is virtualised, so stale on-screen values must be filtered by contiguous runs; a jump can reach a row never drawn. So dimming in advance is dropped: a side dims only once refused.
- [Decide how entry sides without a Jump target show and click](issues/11-grill-unjumpable-sides.md): rows that are on screen but have no site (a local command's echo, a prompt-type command's input, `!cmd`) jump to the nearest drawn row with `center`, counted as jumping to that prompt; rows never drawn (compacted before a resume, left by a rewind) dim in advance, a click does not jump, and the Pane's bottom says why; `ToolGroup` is hooked too; the Current position looks only at drawn rows, now "the last group when the last drawn row is wholly visible"; ↑↓ do not skip dimmed entries.
- [Measure how the Pane redraws with the Current position](issues/10-task-pane-redraw-on-scroll.md): the transcript render hook writes a `$.state` atom through `$.clock.after(0, …)` only when the Current position really changes, and the Pane redraws from it; 0 errors on both versions, median delay 6–7 ms, the transcript hook not run more. invalidate works but doubles the transcript hook's runs; writing state from `Promise.then` is now and then refused; an unconditional invalidate loops on itself. The highlight is kept.
- [Measure how requestId maps to transcript rows](issues/09-task-map-request-id-to-transcript.md): `requestId` is the transcript row's `uuid` (unchanged after resume); `onScreen` matches the screen line by line, so the highlight's premise holds. A slash command's input row, `!cmd`'s rows, rows thrown away by a rewind and most rows before a compaction after a resume have no Jump target; `"placeholder"` is ignored; a render hook may not write `$.state`.
- [Decide whether to highlight the current position](issues/08-grill-scroll-spy.md): yes, on the premise measured with requestId, dropped without notice if it fails; highlight the group of the viewport's top line, the last group when the last line is wholly visible; separate from the ↑↓ selection cursor; the TOC's scrolling always follows the highlight, paused by a manual scroll or the Pane's focus.
- [Check the key APIs on Claude Code 2.1.287](issues/07-task-verify-2-1-287-api.md): every item on the list (`onScreen`, `session.append`/`end`, `UiScrollTarget`, Pane props, `ui.close` origin, `fs.read`/`stat`, `process.run`, `transcript_path`) is on 2.1.287 with the same fields as 2.1.295; a minimal mod validates, so the minimum version need not rise. A new session's transcript file does not exist before the first message.
- [Define the Turn group's split and edges](issues/04-grill-turn-group-model.md): the transcript file is the data source, rows taken along the current branch's conversation chain, and which user rows open a group follows cc-switch (`!cmd` opens one too); steps = the main loop's `tool_use` count, the last text = the text after the last tool; interruption, error and time come exactly from the file, in progress from turn events; large files are read in incremental chunks by offset.
- [Research the details of cc-switch's conversation contents](issues/03-research-cc-switch-toc.md): a turn opens at each user message that is not injected, the contents render in full and do not change with the filter, scroll-spy takes the turn of the viewport's top, and a click on the Agent side falls back step by step; its slash commands do not show their text, its step counts are inconsistent, and a click under a filter silently does nothing: none of these are copied.
- [Check the docked Pane's lifecycle and placement rules](issues/02-research-pane-lifecycle.md): the official `cc-plugin-diff` is the template: open by itself only when fullscreen, withdraw on `isPlaced:false`; no `closeOnEscape`; scroll and follow the newest on its own to hold `>=2.1.287`; "closed for this session" in `$.state` (reset by `/clear` and `/resume`), the View filter in `$.store`.
- [Check the transcript row enumeration and jump primitives](issues/01-research-transcript-row-primitives.md): a Jump target's `requestId` can only be had while `UserMessage`/`AssistantMessage`/`CommandOutput` is drawn, and a jump must be started by the person; steps and interruptions are exact only for turns in this process; the public API has no timestamps; scroll-spy can use `props.onScreen`, but whether 2.1.287 has it is unproven; a rewind raises no event, so text alignment is the way around.

## Out of scope

- A persistent archive, cross-session history, consent to collect.
- An inline placement (above the prompt) as a fallback for opening by itself (except when the person opens it with `/chat-toc` and the host places it inline).
- Desktop, VS Code, JetBrains, mobile and other non-terminal surfaces.
- Subagent (sidechain) content in the TOC.
- cc-switch's search, export and "changes" view at the top.
