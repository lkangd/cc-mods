# Decide how entry sides without a Jump target show and click

Type: grilling
Status: resolved
Blocked by: 

## Question

Measurement shows that the following User input or Agent reply rows have no drawing site to hook in the transcript, or are not drawn, so they have no Jump target: the echo row of a local slash command (only the next row, the `CommandOutput`, can be jumped to), the input row of a prompt-type slash command, both the input and output rows of `!cmd`, rows thrown away by a rewind, and rows from before a compaction that were not drawn after a resume. How do they show in Chat TOC (as usual, or greyed out; should the reason be given)? What does a click do (jump to the nearest jumpable row, such as a local command to its `CommandOutput` and `!cmd` to the next group; or do not jump, but make the person aware)? Does a local command jumping to its output row count as "jumping to that prompt"? What feedback is given when `$.ui.scroll` returns `nothing drawn under that requestId`? How is the Current position grouped when it lands on these rows?

## Answer

**Handle them in two classes. Class A: rows that are drawn on screen and merely have no site (the local command echo, a prompt-type command's input row, both `!cmd` rows). A click jumps to the nearest drawn row and counts as having jumped to that prompt. Class B: rows that are not drawn (rows from before a compaction after a resume, the old branch left after a rewind). They dim in advance, a click does not jump, and the Pane gives a note.** The host facts this rests on: `$.ui.scroll`'s `block` supports `start | center | end | nearest`; `to: 'start'/'end'` can scroll only this plugin's own Pane, not to the end of the transcript; there is no parameter to jump by a row offset.

1. **Class A fallback jump**: jump to the row that follows it in the transcript and that this process has drawn. A local command jumps to its `CommandOutput`; a prompt-type command's user side jumps to the first drawn row of its group; `!cmd` jumps to the next drawn row, or to the previous one if none follows. The fallback jump uses `block: 'center'`, so the original input row stays on screen above the target row; a direct jump stays at `start`. The entry's style does not tell them apart and gives no note. When the target row is taller than a screen, the original input row is cut off; that cost is accepted.
2. **Also hook `ToolGroup`**: read only its `requestId` (`collapsed-<prefix of the first tool_use row's uuid>`) and `onScreen`, change no drawing, and use it for both the fallback jump and the Current position, so a prompt-type command's fallback target does not land after a long run of tools. Whether the prefix matches a uuid uniquely, whether a non-collapsed display goes through `ToolUse` instead, and how many more hook runs there are goes to the prototype to measure; if it does not hold, fall back to the three sites `UserMessage`/`AssistantMessage`/`CommandOutput`.
3. **Class B dims in advance**: the mod notes the `requestId`s its render hook has seen in this process. A side that was never drawn still shows its original text, but dimmed; a click or Enter does not jump and the Pane gives a line of note. This presumes the fullscreen transcript is not virtualised, that is, rows off screen are drawn too and enter the set. If the prototype finds it is virtualised, drop the dimming in advance and only give the note when a jump is refused.
4. **Feedback when a jump is refused**: when `$.ui.scroll` returns `nothing drawn under that requestId` or any other error, show a line of note at the Pane's bottom. It goes at the next jump, selection move or after about 5 seconds (`$.clock`); the refused side then dims, until it is drawn again. The note states the fact and does not guess the cause (a rewind leftover and a pre-resume compaction cannot be told apart), worded like "This entry is not in the conversation view now; cannot jump to it". `"placeholder"` is never taken as a target.
5. **The Current position looks only at drawn rows**: it is decided by the foremost hooked row on screen, and grouped by the rule in "Decide whether to highlight the current position". A group with no drawn row (a lone `!cmd` group, a group from before a resume) is never highlighted. "Force the last group when the transcript's last row is wholly visible" becomes "force the last group when the last drawn row is wholly visible", so when the last group is a `!cmd`, scrolling to the bottom can still highlight it.
6. **Keyboard**: with the Pane focused, the ↑↓ selection cursor still stops on dimmed entries, and Enter reacts the same as a click; these entries are not skipped.

Term: `mods/chat-toc/CONTEXT.md`'s Jump target gains the meaning of falling back to the nearest row.

## Later revisions

- Revised after the measurements in "Prototype the docked TOC Pane's look and interaction": item 3's dimming in advance is dropped, so every jump is tried first and a side dims only once refused; item 1's fallback becomes the nearest drawable row after, or before when none follows, with `center`, trying the next candidate on a refusal; item 5's Current position gains a lock after a jump.
