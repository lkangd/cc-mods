# 22: 大文件分块与增量读取

**What to build:** transcript 超过 4 MiB 也能完整读出目录，会话继续时只读新增部分、只重组末组；文件读不了或有认不出的行时，Pane 如实说明，不拼凑一份冒充完整的目录。

规格见 [chat-toc MVP](../spec.md) §3。

**Blocked by:** 17（自动停靠的最小目录）

**Status:** ready-for-agent

- [ ] 首次读且 >4 MiB，或任何增量读取，在 macOS/Linux 用 `dd` 定位加 `head` 从字节偏移读 4,000,000 B；Windows 构造 Windows PowerShell 5.1 `[IO.File]` 按偏移读、base64 输出的命令
- [ ] 每块截到最后一个换行，偏移加保留部分的 UTF-8 字节数；半行跨块边界时结果与整份读取一致（CT-DATA-004）
- [ ] 单行超过一块时按「无法识别的行」计数并跳过
- [ ] 文件变小时整份重读；新叶子能回溯到旧链末行时保留旧链、只从末组开组行起重组，否则整份重组；增量结果与整份重组逐组一致
- [ ] 读失败或无权限时不显示任何条目，底部常驻原因，不用 `$.session.messages()` 拼凑（CT-DATA-002）
- [ ] 无法识别的行跳过，底部说明「有 N 行无法识别，目录可能不完整」，N 为实际计数（CT-DATA-003）
- [ ] 自动化测试覆盖分块边界、半行、超长行、增量与整份一致；Linux 与 Windows 只用 `$.process.run` 替身核对命令构造与输出解析
