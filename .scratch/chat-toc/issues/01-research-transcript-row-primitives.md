# Check the transcript row enumeration and jump primitives

Type: research
Status: resolved
Blocked by: 

## Question

In the public mods API of Claude Code `>=2.1.287` (checked against the local 2.1.295), can a mod: (1) enumerate the current transcript's main-loop User input rows (slash commands, `!` shell and everything else submitted with Enter) and assistant text rows, getting for each an identity it can pass to `$.ui.scroll({ to: { requestId } })`; (2) jump to an assistant text row, not only a prompt row; (3) tell the main loop from subagents, and system-injected user rows (task notifications, hook injections, compaction summaries) from typed ones; (4) count a turn's tool steps and tell whether a turn is in progress or interrupted; (5) get each message's timestamp; (6) learn the transcript's visible area or scroll position (deciding whether scroll-spy is possible); (7) get reliable change notices after `/clear`, compaction, rewind and resume. For each, give the event/method name, the version it is available from (judged from the changelog: is it in 2.1.287) and what remains uncertain until a prototype measures it.

## Answer

The research document is `docs/research/chat-toc/01-transcript-row-primitives.md` on branch `research/chat-toc-transcript-row-primitives` (not merged), ending with a list of 7 items to measure, by risk. How versions were judged: comparing the repository's 2.1.273 and 2.1.290 type declarations, anything already in 2.1.273 is "certainly in 2.1.287"; anything only in 2.1.290 and not marked with a version is "likely, unproven".

1. **Enumeration and identity**: yes, but only while a row is drawn. The `e.requestId` of `ui.render`'s `UserMessage`, `AssistantMessage` and `CommandOutput` sites is the `$.ui.scroll` target; the person's input is told by `props.origin.kind === 'composer'`, excluding `placeholder`. `AssistantMessage` is drawn per block, so one reply has several ids (`isFirstOfReply`, `isSummary`). The rows of `$.session.messages()` have no id and can only be aligned by text. (Certain.) To measure: which site draws a slash command's echo and a `!` shell row, with which origin; whether every row of a long resumed session is drawn at least once.
2. **Jumping to an assistant row**: allowed by the contract, but only when the person started it (such as a Button's onPress); otherwise `{ deny: 'not person-initiated' }`. Only prompt rows were checked in a 2.1.290 PTY; summary blocks, collapsed tool groups, remote rows and jumps started from a docked Pane remain to measure.
3. **Main loop vs subagents / injected rows**: the drawing layer has no `agentId`, but `origin.kind` (`task-notification`, `peer`, `plugin`, `unclassified` and so on) tells most sources apart; `session.append`'s `agentId`, `door` and `isMeta` tell them all (likely). To measure: whether subagents, hook injections and compaction summaries are drawn in the main transcript.
4. **Steps and state**: exact for turns in this process (`turn.start`, `turn.step`, `tool.call` counted by `agentId`/`turnId`, `turn.complete`'s `reason`/`isAborted`, each row's `ToolUse.isRunning`/`isInterrupted`); historical turns brought back by resume can only be approximated from `messages()`' `toolUses`, with no structured field for interruption. Turns formed by slash commands and `!` raise no turn events.
5. **Timestamps**: the public API gives none. Alternatives: live, stamp `$.clock.now()` at append or first draw; history only by reading `transcript_path`'s JSONL (unpublished format, 4 MiB per file), which breaks "public API only".
6. **Visible area**: each transcript site has `props.onScreen = { first, last, of }` (`null` off screen, render rerun on change), enough for scroll-spy; fullscreen only. **The biggest risk**: not in 2.1.273, in 2.1.290, mentioned by neither the docs nor the changelog, so whether 2.1.287 has it is unproven.
7. **Change notices**: `/clear` and resume have `session.end`'s `reason` (likely) and classic `SessionStart.source` (certain); compaction has `session.compact` and classic `PreCompact`/`PostCompact` (certain); **a rewind raises no event**, so the only way, as prompt-history did, is the `PromptHint` redraw, rereading `messages()` and aligning by text. Leaving a session may redraw old rows, and those draws must be ignored meanwhile.
